Scope: browser, Next BFF, OIDC, Java, FastAPI, PostGIS, Redis, ingestion, CI and local
EVM attestations. The trust-boundary diagram is in [architecture](../../../security/architecture.md).
Assume Internet-controlled request bodies, malicious retrieved text, guessed UUIDs,
stolen short-lived tokens, compromised dependencies and administrator mistakes.

| STRIDE                 | Concrete threat                                                       | Implemented control                                                                                                                                                         | Residual / verification                                                                                                      |
| ---------------------- | --------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------- |
| Spoofing               | Stolen identity / forged tenant / login CSRF                          | PKCE, state, nonce, signed tokens, issuer/audience/lifetime/tenant checks, active DB membership, Secure opaque session cookie, optional exact ACR                           | IdP setup, recovery and MFA enrollment are external; session/claim tests are not proof of real-provider deployment           |
| Tampering              | Change snapshot values or cross-tenant references                     | Server-derived immutable snapshots, tenant+owner predicates, fixed SQL, DTO/parser limits, idempotency, input/result hashes                                                 | Authorized providers may still report incorrect facts; hashes prove integrity, not truth                                     |
| Repudiation            | Deny role change, allocation or attestation                           | Transactional sensitive-action audits, generated request IDs, model/solver version and scenario fingerprints, chain receipts                                                | DB owners can alter logs; external immutable log sink remains a deployment requirement                                       |
| Information disclosure | Browser service-token delegation, leaked sessions, PII in logs        | Explicit local mode, shared auth helper, AES-GCM server sessions, no refresh-token persistence, no body/token/IP logging, source minimization, no-store, scope intersection | Bearer theft remains possible; backups, Redis ACLs/TLS and edge logs require operator configuration                          |
| Denial of service      | Deep JSON, huge import, arbitrary model calls, expensive optimization | Streaming size bound, CSV limits, nesting caps, Redis request limits, bounded solver and inference concurrency, provider budgets/timeouts                                   | Pre-auth ingress DDoS controls and infrastructure quotas must be deployed; known developer dependency advisory is documented |
| Elevation of privilege | UI persona spoof, stale role, arbitrary SQL/tool, last-admin removal  | Server method scopes, per-request membership narrowing, tenant/owner queries, ID-only LLM responses, lifecycle lock                                                         | Tenant administrator can still grant roles; separation of duties and approval workflow are not implemented                   |

Specific abuse cases to test: unauthorized reads/exports, foreign city/source IDs,
disabled memberships, malformed/missing tenant claims, MFA mismatch, expired session,
replayed login flow, invalid callback state/nonce, cross-site mutation, malicious
CSV headers, injection instructions in sources, malicious contract callers and
duplicate attestations. Existing Solidity tests cover roles and replay/duplicate
paths; a professional contract audit and full penetration test remain pending.
